# pairwise-transcode-pipeline

批量转码任务跑了一晚上，产出里混进了比源文件还大的 4K 档，竖屏视频被拉成横屏，字幕烧录时冒号被当成参数分隔符直接报错，断点续跑还把已经完成的段又转了一遍。查下来是 transcode/pipeline.py 的转码流水线有严重问题：plan_ladder() 不管源分辨率和源码率，固定返回整张阶梯，4K 档也照发；rendition_size() 写死 1280x720，4:3 素材直接被拉变形；build_filter_chain() 把滤镜按名字排序，顺序和调用方给的完全不一致，参数里的逗号和冒号也不转义，drawtext 一遇到标点就解析失败，未知滤镜和缺参数都不报错；select_subtitle() 只做语言字符串全等匹配，zh-Hans 和 chi 认不出来，强制字幕不优先，烧录还标成可以直接 copy；resume_plan() 永远从头开始，已完成段重复转码，检查点中间缺段也照样往后跑。你要修的是：阶梯按源分辨率和源码率裁剪并支持码率上限；缩略尺寸按宽高比换算并保证偶数；滤镜链保持调用顺序、转义特殊字符、校验滤镜名和参数个数；字幕按语言标签归一化匹配、优先强制轨、跳过禁用轨、烧录标记需要重编码；断点续跑只跳过连续完成的段，检查点有缺口就整体重跑。transcode/pipeline.py 是核心，tests/test_pipeline.py 15个红。

## 运行

```
python -m pytest tests -q
```
